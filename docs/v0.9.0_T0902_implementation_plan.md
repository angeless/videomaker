## 2. 本轮实施计划

### 步骤 1: 安装 Playwright + 配置

在 `apps/desktop/ui-vue/` 中：
- `npm install -D @playwright/test`
- 创建 `playwright.config.js` — 配置 baseURL、webServer（Vite + Flask）、timeout
- 在 `package.json` 中添加 `"test:e2e"` script

### 步骤 2: 创建测试辅助设施

- `tests/e2e/helpers/test-server.js` — 辅助函数（等待服务就绪等）
- `tests/e2e/fixtures/` — 目录占位（本轮不需要真实媒体文件，API mock 足够）

### 步骤 3: 编写 5 个核心路径测试

按 PRD 定义的 5 条路径：

| Spec 文件 | 核心路径 | 验证内容 |
|-----------|---------|----------|
| `onboarding.spec.js` | 首次打开 → 引导弹窗 → 跳过 → 不再弹出 | 弹窗渲染、跳过按钮、localStorage 持久化 |
| `library.spec.js` | 素材库 → 搜索 → 结果展示 | 页面加载、搜索框、结果区域 |
| `publish.spec.js` | 发布面板 → 选择 blog → 查看结构化结果 | 面板渲染、平台选择 |
| `export.spec.js` | 社媒导出 → 选择平台卡片 → 计划展示 | 导出面板、平台卡片 |
| `settings.spec.js` | 设置页面 → 修改 AI provider → 保存 | 设置渲染、表单交互、保存反馈 |

### 步骤 4: 验证测试运行

- 启动 Flask + Vite dev server
- 运行 `npx playwright test`
- 确保 5 个 spec 全部通过

### 实现策略

**关于 Flask 后端**:
- Playwright webServer 配置可以只启动 Vite dev server
- Vite 的 proxy 会将 `/api` 请求转发到 Flask 9527
- 测试前需要确保 Flask 已在 9527 运行（或通过 Playwright 的 webServer 配置同时启动）
- 安全 token 在测试环境中通过 `/api/session/bootstrap` 获取，或测试配置中关闭

**测试稳定性**:
- 使用 Playwright 的 `page.waitForSelector` 而非固定延时
- API 返回慢时使用 `page.waitForResponse` 等待
- 超时配置合理（30s per test）

## 6. 风险与缓解

| 风险 | 缓解 |
|------|------|
| Flask 服务未启动导致 API 调用失败 | Playwright webServer 配置中同时启动 Flask |
| 安全 token 阻断测试请求 | 测试 Flask 实例中关闭 `_REQUIRE_LOCAL_API_TOKEN` |
| Onboarding 弹窗依赖 localStorage | 测试前清理 localStorage |
| npm install 网络超时 | 使用 npm mirror 或 retry |
