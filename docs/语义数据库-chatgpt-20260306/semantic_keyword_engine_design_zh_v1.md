# 语义关键词系统落地设计（数据库 + 打分规则 + 自定义扩展）
版本：v1  
语言：中文  
适用对象：本地视频 / 图片语义识别软件  
兼容方式：作为 `semantic_keyword_library_zh_v1.json` 的工程化补充

---

## 1. 设计目标

你前面的关键词库解决的是“有哪些词可以识别”，这一版解决的是“识别结果如何落库、如何打分、如何扩展”。

建议把整套能力拆成 4 层：

1. **基础词库层**：标准关键词、层级分类、同义词、关系词
2. **识别证据层**：视觉模型、OCR、ASR、字幕、文件元数据、时间线
3. **决策融合层**：打分、去重、冲突处理、复合语义、时序平滑
4. **学习扩展层**：用户自定义词、高频新词发现、人工审核入库

---

## 2. 推荐系统架构

```text
本地图片/视频
   ↓
帧抽样 / 镜头切分 / 音频抽取
   ↓
基础识别
   ├─ 视觉检测（物体 / 场景 / 人脸 / 动作）
   ├─ OCR（屏幕文字 / 路牌 / 海报 / 包装）
   ├─ ASR（视频语音 / 对白 / 解说）
   ├─ Metadata（拍摄时间 / GPS / 文件夹名 / 文件名）
   ↓
语义归一化
   ├─ 同义词映射
   ├─ 别名映射
   ├─ 复合规则推理
   ├─ 负向规则排除
   ↓
标签打分
   ├─ 单标签置信分
   ├─ 父子标签传播
   ├─ 时序平滑
   ├─ 多证据融合
   ↓
结果落库
   ├─ 资源表
   ├─ 标签表
   ├─ 识别结果表
   ├─ 自定义词表
   ├─ 待学习新词表
   ↓
用户反馈
   ├─ 确认正确
   ├─ 确认错误
   ├─ 新增别名
   ├─ 新增自定义词
   ↓
扩展学习 / 审核入库
```

## 3. 推荐标签体系字段

每个关键词不要只存一个名字，建议至少包含这些字段：

| 字段 | 含义 |
|---|---|
| tag_id | 标签唯一 ID |
| tag_name | 标准标签名 |
| tag_type | 标签类型，如地点/场景/物品/动作/人物 |
| parent_id | 父标签 |
| level | 层级深度 |
| aliases | 别名、口语、俗称 |
| synonyms | 同义词 |
| related_tags | 相关词 |
| negative_tags | 排斥词/冲突词 |
| trigger_objects | 触发物体 |
| trigger_scenes | 触发场景 |
| trigger_texts | OCR / ASR 可触发文本 |
| score_threshold | 生效阈值 |
| is_custom | 是否用户自定义 |
| is_active | 是否启用 |
| review_status | 审核状态 |
| created_by | 系统/用户/运营 |
| source | 来源（系统库/自动学习/用户新增） |

## 4. 推荐数据库表结构

下面是建议的最小可用表集：

### 4.1 主数据表

1. **tag_category**  
   顶层分类，例如 地点 / 场景 / 物品 / 人物 / 动作 / 时间与环境

2. **tag**  
   标准标签主表

3. **tag_alias**  
   标签别名/口语/同义词映射

4. **tag_relation**  
   父子关系、相关关系、冲突关系、共现关系

5. **composite_rule**  
   复合语义规则，例如：
   - 锅 + 灶台 + 厨房 + 切菜 → 做饭
   - 电脑 + 会议室 + 投影仪 → 开会 / 办公

### 4.2 媒体资源表

6. **asset**  
   媒体文件主表，存图片/视频基本信息

7. **asset_segment**  
   视频镜头段 / 时间段；图片可只保留一条全局 segment

8. **evidence**  
   原始识别证据表，记录“这个标签是怎么来的”

9. **asset_tag_result**  
   最终标签结果表，记录融合后的标签分数

### 4.3 用户扩展与学习表

10. **custom_tag**  
    用户自定义标签主表

11. **custom_tag_mapping**  
    用户自定义词与系统词的映射关系

12. **learning_candidate**  
    自动学习发现的新词候选池

13. **feedback_event**  
    用户对识别结果的反馈日志

14. **tag_version_log**  
    词库变更日志，便于回滚和审计

## 5. 标签打分核心思路

不要让模型输出什么就直接信什么。建议把分数拆成：

```text
最终分 = 基础模型分 × 证据权重 × 规则修正 × 时序修正 × 用户修正
```

更推荐的工程化公式：

```text
final_score =
  clamp(
    base_score
    + source_bonus
    + cooccurrence_bonus
    + hierarchy_bonus
    + custom_boost
    - conflict_penalty
    - negative_penalty
    + temporal_smooth,
  0, 1)
```

### 5.1 基础分 `base_score`
来自单个模型或单条规则：
- 视觉检测：0~1
- OCR 关键词命中：0~1
- ASR 文本命中：0~1
- 文件元数据命中：0~1

### 5.2 证据权重建议

| 证据源 | 推荐权重 |
|---|---:|
| 视觉目标检测 | 1.00 |
| 场景分类 | 0.95 |
| 动作识别 | 0.95 |
| OCR 文本命中 | 0.75 |
| ASR 文本命中 | 0.72 |
| 文件名/文件夹名 | 0.45 |
| EXIF/GPS/拍摄时间 | 0.55 |
| 用户历史确认 | 1.10 |
| 自定义规则直接命中 | 1.15 |

注意：这不是最终分，而是“对基础分的可信度修正”。

### 5.3 共现加分 `cooccurrence_bonus`

当多个标签同时出现，可以给上层语义加分。例如：

- `沙发 + 茶几 + 电视` → `客厅` +0.10 ~ +0.18
- `床 + 衣柜 + 台灯` → `卧室` +0.10 ~ +0.18
- `锅 + 燃气灶 + 冰箱` → `厨房` +0.12 ~ +0.20
- `黑板 + 课桌 + 学生` → `教室` +0.12 ~ +0.22
- `雪地 + 羽绒服 + 呼气白雾` → `冬季` +0.15 ~ +0.25

### 5.4 层级加分 `hierarchy_bonus`

如果子标签高分出现，父标签应自动获得传播分：

- `厨房` 高分命中 → `室内居住空间` 自动加分
- `篮球比赛` 高分命中 → `体育与竞技` 自动加分
- `海边日落` 高分命中 → `自然风景` 与 `黄昏` 可低幅加分

建议：
- 子 → 父传播系数：0.18 ~ 0.35
- 父 → 子不要反向硬推，只可作为弱提示（0.03 ~ 0.08）

### 5.5 冲突扣分 `conflict_penalty`

互斥标签同时高分时，应该扣分或只保留更高的一侧：

- `白天` vs `夜晚`
- `室内` vs `户外`
- `晴天` vs `暴雨`
- `厨房` vs `卧室`
- `独处` vs `大型聚会`

### 5.6 负向规则 `negative_penalty`

例如：
- 命中“婚礼现场”时，如果没有白纱、礼堂、舞台、花门等证据，则别轻易上 `婚礼`
- 命中“医生”时，如果只是白大褂广告图，不一定是真医疗场景
- 命中“下雪”时，若只是白色滤镜或泡沫特效，要降权

### 5.7 时序平滑 `temporal_smooth`

对视频非常关键。建议按 segment 或滑动窗口平滑：
- 连续 3 个 segment 都命中 `厨房`，后续段可 +0.05
- 单帧误检出现一次，下一段消失则快速衰减
- 场景类标签衰减慢，物体类标签衰减快

建议：
- 场景类平滑窗口：3~8 秒
- 物体类平滑窗口：1~3 秒
- 动作类平滑窗口：0.5~2 秒

## 6. 自定义关键词机制

这是你产品很重要的差异化点。建议不要把用户自定义词直接混进系统主表，而是走“双层机制”：

### 6.1 双层机制
- **系统标准库**：官方维护，可版本化
- **用户扩展库**：每个用户/团队自己维护

### 6.2 自定义词推荐字段

| 字段 | 示例 |
|---|---|
| custom_tag_name | 老家院子 |
| normalized_name | 农村庭院 |
| parent_system_tag | 庭院 / 乡村 / 户外 |
| aliases | 老院子, 家里院子 |
| related_objects | 树, 土墙, 狗, 玉米, 拖拉机 |
| related_scenes | 农村生活, 家庭活动 |
| trigger_texts | 老家, 回村, 院子 |
| negative_texts | 室内, 城市公寓 |
| threshold | 0.72 |
| auto_expand | true |
| review_mode | manual / semi-auto |

### 6.3 用户新增词的安全流程
1. 用户创建自定义词
2. 系统要求至少绑定一个父标签
3. 系统自动推荐别名/相关词
4. 新词先进入“灰度启用”
5. 命中次数达到阈值后再正式启用
6. 自动学习只能写入候选池，不能直接改系统主库

## 7. 自动学习建议

“AI 自我学习”不要理解成让模型自己乱长词。更稳的方式是“**候选发现 + 人工审核 + 渐进纳入**”。

### 7.1 候选来源
- 高频未登录词
- OCR/ASR 高频短语
- 用户经常手动修正的标签
- 总被一起命中的新组合
- 用户创建的自定义词别名

### 7.2 候选入池条件
至少满足下面任意 2 项：
- 7 天内出现次数 ≥ 20
- 来自 5 个以上不同资源
- 与某正式标签共现概率 ≥ 0.6
- 用户手工确认次数 ≥ 3
- OCR 与视觉双证据同时命中

### 7.3 审核动作
- 合并到已有标签别名
- 升级为新标签
- 作为复合规则触发词
- 丢弃为噪声词

### 7.4 不建议自动入主库的内容
- 明显脏词、广告词、随机口头禅
- 高歧义词，如“冲”“炸”“开了”
- 时效太强的热梗
- 仅在单一用户出现的私有词，除非进入该用户扩展库

## 8. 复合语义规则示例

### 8.1 场景推理
- `沙发` + `电视` + `茶几` → `客厅`
- `床` + `枕头` + `床头柜` → `卧室`
- `锅` + `灶台` + `案板` → `厨房`
- `黑板` + `课桌` + `老师/学生` → `教室`
- `跑步机` + `哑铃` + `镜子` → `健身房`

### 8.2 行为推理
- `锅` + `菜板` + `切菜动作` → `做饭`
- `电脑` + `键盘` + `坐姿` + `办公桌` → `办公`
- `麦克风` + `舞台` + `人群` → `演出`
- `方向盘` + `车窗移动背景` → `开车`

### 8.3 时间/天气推理
- `雪` + `厚外套` + `灰白天空` → `冬季`
- `强阳光` + `墨镜` + `短袖` → `夏季`
- `雨伞` + `水面反光` + `雨声/下雨文本` → `雨天`

### 8.4 地点推理
- `海浪` + `沙滩` + `比基尼/泳衣` → `海边`
- `高楼` + `车流` + `红绿灯` → `城市街道`
- `稻田` + `农具` + `低层平房` → `乡村`

## 9. 视频与图片的识别差异

### 图片
- 更依赖单帧视觉和 OCR
- 可以适当提高物体类、风格类权重
- 不需要强时序平滑

### 视频
- 必须做 segment 级别识别
- 场景类以镜头段为准，不以单帧为准
- 动作类需要滑动窗口
- 同一视频需要“全局标签”和“时间段标签”两层结果

## 10. 阈值建议

| 标签类型 | 建议展示阈值 | 建议写库阈值 |
|---|---:|---:|
| 物体 | 0.55 | 0.45 |
| 场景 | 0.58 | 0.50 |
| 地点 | 0.60 | 0.52 |
| 动作 | 0.62 | 0.55 |
| 人物身份 | 0.68 | 0.60 |
| 季节/天气 | 0.62 | 0.56 |
| 抽象氛围 | 0.70 | 0.62 |
| 用户自定义词 | 0.72 | 0.65 |

说明：
- “展示阈值”是给用户看的标签
- “写库阈值”可以略低，便于后续聚合和学习

## 11. 推荐索引策略

### 高频检索
- 按资源查标签：`asset_tag_result(asset_id, final_score desc)`
- 按标签查资源：`asset_tag_result(tag_id, final_score desc)`
- 按时间段查视频：`asset_segment(asset_id, start_ms, end_ms)`
- 按用户扩展查自定义词：`custom_tag(user_id, custom_tag_name)`

### 文本检索
- `tag_alias(alias_name)`
- `learning_candidate(candidate_text)`
- 可加全文索引，支持模糊搜索与拼写纠正

## 12. 版本管理建议

建议每次词库变更都记录版本：

- `major.minor.patch`
- 例如：
  - `1.0.0`：初始词库
  - `1.1.0`：新增交通与建筑标签
  - `1.1.1`：修正同义词映射
  - `1.2.0`：新增用户自定义词系统

每次更新要保留：
- 新增标签数
- 删除标签数
- 改名标签
- 合并标签
- 新增别名
- 新增冲突规则
- 新增复合规则

## 13. 接入建议

工程上最稳的接法是：

1. 先把我给你的大词库导入 `tag / tag_alias / tag_relation`
2. 图片走“单资源识别”
3. 视频走“镜头段识别 + 全局聚合”
4. 先做 50~100 条高价值复合规则，不要一开始写几千条
5. 用户自定义词先单独表管理
6. 自动学习只进候选池，不直接改正式词库
7. 先做“可解释分数”，不要一开始就做黑盒打分

---

## 14. 最小可用版本（MVP）建议

如果你准备先快速上线，可以只做这些：

- 标签主表 `tag`
- 别名表 `tag_alias`
- 资源表 `asset`
- 分段表 `asset_segment`
- 证据表 `evidence`
- 结果表 `asset_tag_result`
- 自定义词表 `custom_tag`
- 候选词表 `learning_candidate`

然后配这 5 种能力：
- 同义词归一化
- 多证据加权
- 父子标签传播
- 10~30 条复合规则
- 用户纠错反馈

---

## 15. 一句话总结

真正好用的语义系统，不是“词越多越好”，而是：

**词库结构化 + 证据可解释 + 规则可迭代 + 用户可扩展 + 学习可审核。**

这样你的软件才会从“会打标签”，变成“越用越懂用户素材”。
