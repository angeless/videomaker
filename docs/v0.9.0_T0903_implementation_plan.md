# T-0903 实施计划：发布链路 OpenAPI 文档

## 当前代码现状理解

### 发布链路 API 端点统计
经过源码分析，发布链路涵盖 5 组 API，共计 29 个独立端点（PRD 预估 27 个，实际含 connector/test 等追加端点）：

| 组 | 路由文件 | 端点数 |
|---|---|---|
| content_publish | `routes/capability_content_publish_routes.py` | 6 |
| social_export | `routes/capability_social_export_routes.py` | 10 |
| publish_prep | `publish_prep_api.py` | 3 |
| youtube oauth | `routes/settings_routes.py` | 4 |
| connectors | `routes/settings_routes.py` | 6 |

### 现有基础设施
- **ui_routes.py**：已有静态文件服务 Blueprint，可扩展 `/api/docs/publish` 路由
- **docs/ 目录**：已存放各版本文档，新增 `docs/api/` 子目录
- **API 响应格式**：统一 `{"ok": true, ...}` 或 `{"error": "message"}`
- **input_mode 模式**：大部分端点支持 `project`（需加载项目）和 `inline`（独立运行）两种模式

## 本轮实施计划

### 阶段 1：编写 OpenAPI 3.0 YAML
- 创建 `docs/api/openapi-publish.yaml`
- 覆盖 5 组共 29 个端点
- 每个端点包含：path, method, summary, description, parameters, requestBody, responses (200/400/404/500)
- 每个端点至少 1 个完整请求/响应示例

### 阶段 2：添加静态文件路由
- 在 `ui_routes.py` 中新增 `/api/docs/publish` 路由
- 返回 YAML 文件内容，Content-Type: application/x-yaml

### 阶段 3：验证
- 使用 openapi-spec-validator 做语法校验（AC-01）
- 与源码对照确认端点覆盖率（AC-02）
- 确认每个端点有示例（AC-03）

## 实现约束

1. **手工编写**：PRD 明确要求手工编写确保准确性，不使用自动生成
2. **仅发布链路**：不覆盖非发布相关 API（如 library、workflow 等）
3. **不引入 Swagger UI**：保持轻量，仅提供 YAML 文件
4. **不破坏现有路由**：ui_routes.py 的修改仅追加路由，不改动现有静态文件服务逻辑
5. **严格按源码对照**：参数名、类型、默认值均以路由源码为准

## 测试要求

1. **YAML 语法校验**：使用 `openapi-spec-validator` 库验证 YAML 合规
2. **端点覆盖率**：自动化检查 YAML 中的 paths 与源码路由装饰器对照
3. **示例完整性**：检查每个端点至少有 1 个 example
4. **路由可用性**：通过 Flask test client 验证 `/api/docs/publish` 返回 YAML
5. **后端回归**：确认现有测试无回退
6. **前端构建**：确认 Vite build 通过
