# VideoEditor 桌面应用 — 产品体验评测报告

> 版本: v0.11.0 | 评测日期: 2026-03-21
> 评测方式: Flask 后端 API 全量测试 + 前端组件源码审查 + 模拟完整工作流

---

## 一、评测概述

本次评测通过以下方式进行：

1. **启动 Flask 后端** — 直接启动 `create_app()`，在 127.0.0.1:9527 运行
2. **全量 API 路由测试** — 遍历全部 100+ 个 API 端点，测试响应和数据结构
3. **完整工作流模拟** — 创建测试项目 → 初始化 → Step 1 素材分析 → Step 2 脑暴选题 → 审批推进
4. **前端源码审查** — 阅读 Vue 组件、路由、Store、CSS 样式

---

## 三、高优先级问题

### H1: 新用户首次体验断裂 — 无 Onboarding 引导

**现象**: `onboarding_completed: false` 但启动后直接进入空白界面，没有任何引导流程。

**详情**:
- StartupView 只做了 preflight 自检，通过后直接跳转到 `/create` 或 `/library`
- 新用户看到空白的素材库 + 空白的工作流，完全不知道第一步该做什么
- OnboardingModal.vue 组件存在但从未被触发

**影响**: 100% 的新用户会在前 30 秒产生困惑

**建议**: 首次启动时强制弹出 Onboarding，引导用户完成：选择素材目录 → 导入素材 → 开始第一个项目

---

### H2: 素材库导入后无数据 — Library 与 Project 素材系统割裂

**现象**: 通过 `/api/library/assets` 导入素材返回 `assets: []`，Library stats 始终为 0，但 `/api/materials` 在项目内能看到素材。

**详情**:
- 项目内的素材（通过 `run_step(1)` 分析）存储在 `data/materials.json`
- 全局素材库（Library）存储在 `.video_library/library.db`
- 两个系统之间缺乏自动同步机制
- 用户在 Library 页面导入素材后，工作流 Step 1 不一定能看到
- 反之，项目内分析的素材不会自动进入全局 Library

**影响**: 用户困惑"为什么我导入了素材但搜索不到"

**建议**:
- Library 导入成功后自动出现在项目素材选择列表中
- 项目内分析的素材自动写入 Library（可设置为可选）

---

### H3: AI 功能无降级提示 — 静默失败

**现象**: 未配置 API Key 时，Step 2 脑暴选题仍然返回 `status: done` 和看似正常的结果，实际上是硬编码的 fallback 模板。

**详情**:
- AI 设置页显示 `anthropic_api_key_set: false`、`embedding_status: missing_api_key`
- 但 Step 2 没有警告用户"当前处于降级模式，使用的是模板而非 AI 生成"
- Topic Copy 同样如此 — 生成了一个基于模板的 draft，用户可能误以为是 AI 精心创作的
- DegradationBanner.vue 组件存在但在关键工作流步骤中未展示

**影响**: 用户不知道自己在用"阉割版"功能

**建议**:
- 在所有 AI 依赖步骤的结果中加入明确的降级标记
- 首次使用时引导用户配置至少一个 AI Provider
- 在工作流面板顶部常驻显示 AI 状态

---

### H4: Step 6 粗剪缺少可视化编辑能力

**现象**: Step6Rough.vue 只是一个"生成→预览→审批"的单向流程，用户无法对粗剪结果做任何调整。

**详情**:
- 当前 Step 6 只有 4 个参数：目标时长、最大片段数、转场风格、美颜强度
- 生成后只能播放预览和审批/重新生成
- TimelinePanel.vue 组件已存在（有 Ruler、Playhead、Track、Clip 组件），但在 Step 6 中没有被使用
- 用户无法：调整片段顺序、修改单个片段的入出点、删除不想要的片段

**影响**: 粗剪结果不满意时，用户只能反复"重新生成"碰运气

**建议**: 这正是 v0.12 应该解决的核心问题 — 在 Step 6 中集成 TimelinePanel，支持拖拽调整

---

## 四、中优先级问题

### M1: 素材选择缺乏预览和筛选

**现象**: Step1Materials.vue 只有一个"分析素材"按钮和已选数量显示，没有素材列表、预览、筛选能力。

**详情**:
- 用户无法在 Step 1 中看到有哪些素材
- 无法按时长、质量、场景类型筛选
- 无法预览单个素材的缩略图或元数据
- 唯一的交互是点"分析素材"然后等待

**建议**: Step 1 应展示素材网格视图，支持缩略图预览、勾选、筛选排序

---

### M2: 搜索功能有架构但缺实际效果

**现象**: Library 搜索有三种模式（hybrid/keyword/vector）但实际搜索全部返回空结果。

**详情**:
- hybrid 搜索架构完整，权重配置合理（tag 0.50 + FTS5 0.30 + vector 0.20 + custom 0.10）
- 但 vector 搜索依赖 OpenAI API Key（embedding），未配置时不可用
- keyword/FTS5 搜索需要素材先入库到 Library（而非仅在项目内分析）
- SearchAutocomplete 组件做得很好，但因为没有数据，功能无法体现

**建议**: 确保本地分析的标签/关键词能被 keyword 搜索命中，不依赖外部 API

---

### M3: 项目管理存在历史残留数据

**现象**: `/api/projects` 返回 12 个项目，全部指向 `/tmp/audit_*` 路径，状态均为 `missing`。

**详情**:
- 这些是之前测试/审计遗留的项目记录
- 路径已不存在（`/tmp` 在重启后清空）
- 没有清理机制或"删除项目"功能
- 新用户看到一堆 missing 项目会困惑

**建议**: 添加项目列表清理功能；启动时自动标记不可用项目

---

### M4: 工作流步骤之间缺乏上下文传递提示

**现象**: 审批 Step 1 后自动推进到 Step 3（跳过 Step 2 的显式等待），用户不清楚每步之间的依赖关系。

**详情**:
- Step 1 审批 → 自动触发 Step 2 job → Step 2 完成进入 waiting_review
- 但用户在 UI 上看到的是 Step 1 的审批按钮，不知道 Step 2 已经在后台运行了
- 缺少步骤间的状态流转可视化

**建议**: WorkflowStepper 应该实时显示每步状态、当前焦点步骤、以及"后台正在运行"的提示

---

### M5: 渲染配置默认值需要调整

**现象**: 默认渲染配置为 `1080×1920`（竖屏），但 `aesthetic_preset: travel_story` 通常需要横屏。

**详情**:
- 默认输出尺寸 1080×1920 是竖屏短视频规格
- 但默认美学预设 `travel_story` 通常适合横屏叙事
- 用户可能不注意到尺寸设置，导致素材被裁切
- 配置项散落在多处，没有统一的"项目模板"概念

**建议**: 创建项目时提供模板选择（竖屏短视频 / 横屏 Vlog / 自定义），自动关联合理的默认参数

---

## 五、低优先级问题

### L1: 前端国际化不完整

**现象**: 部分文案写死中文（如"分析素材"、"重新生成"），部分通过 labels.js 管理。混合状态。

---

### L2: 暗色主题下对比度不足

**现象**: 背景色 `#0f0f0f`，部分 `.text-muted` 文案的对比度可能不达 WCAG AA 标准。

---

### L3: Canvas 工作流编排器存在但入口不明显

**现象**: CanvasView.vue 和完整的 Canvas 节点编辑系统已实现（Board、Node、Edge、Minimap、Toolbar），但在主导航中不容易发现。

---

### L4: 社交导出覆盖面广但缺乏实际连接

**现象**: 14 个平台的导出规格齐全，但只有 YouTube OAuth 有实际实现。其他平台需要手动复制。

## 八、总结

VideoEditor v0.10.0 的后端架构和功能模块已经相当丰富，API 设计规范、错误处理完善、扩展性良好。主要的差距在于：

1. **新用户体验空白** — 没有引导，第一印象是"空白+困惑"
2. **数据管道断裂** — Library 和 Project 素材系统需要打通
3. **AI 降级透明度不足** — 用户不知道功能在降级运行
4. **粗剪阶段缺少交互** — 生成后无法调整，只能碰运气重试

这些发现进一步支持了 v0.12 的核心方向：增强语义分析、集成拖拽时间线到粗剪、改善整体用户体验。
