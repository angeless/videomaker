### 3.6 对抗性审计

结果为 0 违规，输出最可能违规的 3 个点：

1. **`_find_ffmpeg()` 重复定义 (video_detector.py / render_pipeline.py / scene_segmenter.py)**
   - 合规原因：三处实现完全相同，属于轻微代码重复而非架构违规。coding-standards 未明确禁止模块内部工具函数重复。按 architecture.md review_engine 是独立模块，不应引入跨模块依赖来复用，模块内可接受。
   - 建议：v0.15.0 可考虑提取为 `review_engine/_ffmpeg_utils.py` 内部工具函数。

2. **roughcut_routes.py 的 `except Exception as e` (L77)**
   - 合规原因：这是 video detection 的降级处理（检测失败 → 默认 mixed），符合 coding-standards §4.2 降级策略。有 logger.warning 记录。非 bare except，有错误信息传递。
   - 建议：可以细化为 `except (VideoDetectionError, FileNotFoundError, OSError)`。

3. **roughcut_routes.py 的内存缓存 `_session_data: OrderedDict`**
   - 合规原因：有 `_MAX_CACHED_SESSIONS = 20` 上限和 LRU 淘汰策略，长期运行不会内存泄漏。这是桌面应用场景下的合理设计。
   - 建议：已有防护，合规。

## 6. 发现的问题

### Issue #1: _find_ffmpeg() 重复定义 (LOW)

**位置：** video_detector.py:28, render_pipeline.py:25, scene_segmenter.py:24

**问题：** 同一个 FFmpeg 路径查找函数在 3 个文件中重复实现。

**影响：** 代码重复 ~20 行 × 3 = ~60 行。修改 FFmpeg 查找逻辑需改 3 处。

**建议：** v0.15.0 提取为 `review_engine/_ffmpeg_utils.py` 内部工具函数。

**状态：** 记入 WISHLIST（非阻塞）

### Issue #2: roughcut_routes.py 宽泛异常捕获 (LOW)

**位置：** roughcut_routes.py:77 `except Exception as e`

**问题：** Video detection 降级使用了宽泛的 Exception 捕获。

**影响：** 可能遮蔽非预期错误（如 PermissionError）。

**建议：** 细化为 `except (VideoDetectionError, FileNotFoundError, OSError)`。

**状态：** 记入 WISHLIST（非阻塞，当前有 logger.warning 记录）
