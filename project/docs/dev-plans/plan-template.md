## 〇、写作前检查清单 [必选]

> **在动笔之前，必须逐项完成以下步骤。跳过任何一步都会导致计划与实际代码冲突。**

- [ ] **读代码** — 用 git show / git ls-tree / 直接阅读确认现有模块、表结构、API、前端页面的真实状态
- [ ] **读项目技术规范** — 特别是 dev-governance.md（版本号/测试/文档产出/任务闭环/命名规范），确保计划不与已有规范冲突
- [ ] **读架构文档** — architecture.md 中的分层结构、模块边界、依赖方向，确保新设计不违反架构约束
- [ ] **读 PRD** — 确认目标功能在 PRD 中的定义，不自行发明需求
- [ ] **做 Gap 分析** — 列出"需求需要什么" vs "现在已经有什么"，只针对 Gap 制定任务
- [ ] **检查编码标准** — coding-standards.md 中的目录结构、命名约定、错误处理模式，确保计划中的文件路径和模块命名合规

## 一、开发管理总原则 [必选]

1. **不推倒重写** — 基于已有代码增量开发
2. **继承已有能力** — 列出具体的已有 service / middleware / module / infra（见第二章）
3. **最小改动** — 不改与当前任务无关的文件
4. **不与已有架构冲突** — 新增模块独立目录，必须改已有文件时明确写出改哪个文件的哪个方法以及为什么
5. **每次只能领取一个任务** — 完成汇报确认后再领下一个
6. **引用项目已有规范，不另起炉灶** — 版本号、命名、测试、文档产出等规则引用项目技术规范的章节号
