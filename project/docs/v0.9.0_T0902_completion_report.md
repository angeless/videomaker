## 实现要点

### 测试架构
- **双 webServer 模式**：Playwright 同时启动 Flask API 服务器（端口 9527）和 Vite 开发服务器（端口 5173），通过 Vite proxy 转发 `/api` 请求
- **Flask 测试服务器**：禁用 `_REQUIRE_LOCAL_API_TOKEN` 和 `_REQUIRE_CSRF_PROTECTION`，避免测试环境需要认证
- **`waitForAppReady()` 模式**：所有测试先 `goto('/')`，等待 StartupView 完成初始化并自动跳转到 `/#/library` 或 `/#/create`，再关闭可能出现的 onboarding 弹窗

### 关键技术发现

1. **Vue Hash 路由需要客户端导航**：`page.goto('/#/settings')` 会触发完整页面重载，丢失 Pinia store 状态。解决方案：使用 `page.evaluate(() => { window.location.hash = '#/settings' })` 进行客户端路由跳转。

2. **Pinia store 通过 Vue app 实例访问**：Vue 3 挂载在 `#app` 元素上（`app.mount('#app')`），`__vue_app__` 属性在挂载点而非子元素 `#app-root` 上。

3. **OnboardingModal 触发机制缺失**：`initializeApp()` 虽导出但从未被调用（`StartupView.runStartup()` 有独立的初始化流程），导致 `showOnboardingWizard` 永远为 false。测试通过直接操作 Pinia store 触发向导组件。

4. **SettingsView `reactive` 未导入**（Bug fix）：`webhookForm` 使用了 `reactive()` 但未 import，导致组件 setup 阶段 ReferenceError，设置页面完全无法渲染。E2E 测试发现并修复。
